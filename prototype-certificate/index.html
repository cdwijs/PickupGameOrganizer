Signing Prototype

Generate a public/private key pair in the browser, sign a message with the private key, and verify the signature with the public key. Each step is a button; the time it takes is shown next to it.

Algorithm

Pick the signature and hash algorithms below. Changing either resets everything downstream, since the key material is bound to the algorithm.

Ed25519 uses SHA-512 internally and ignores the hash choice above (the explicit Hash message step will still compute the selected digest as a demonstration).

1 Generate key pair — ms

Creates a new key pair for the selected algorithm using the browser's SubtleCrypto. The private key never leaves the page.

No keys yet.

2 Export public key — ms

Exports the public key in SPKI (X.509 SubjectPublicKeyInfo) form, then base64s it. This is what you would hand to a verifier. 


    


    

      
3 Export private key
        — ms
      

      

        Shown for demonstration only. Exports the private key in PKCS#8 form,
        base64-encoded. In a real app you would keep this in IndexedDB as a
        non-extractable CryptoKey, never as text.
      

      

        
      

      
      

    


    

      
4 Encode message
        — ms
      

      

        Turns the text below into raw UTF-8 bytes. Signing operates on bytes, not
        strings — this step makes that explicit.
      

      
      
      

        
      

      
      

    


    

      
5 Hash message
        — ms
      

      

        Computes SHA-256 of the encoded bytes. ECDSA actually signs the digest, not
        the raw message; the sign step below does this internally, but hashing it explicitly here
        shows what is being signed.
      

      

        
      

      
      

    


    

      
6 Sign
        — ms
      

      

        Signs the encoded message with the private key using the selected algorithm.
        The output size depends on the algorithm — 64 bytes for ECDSA/P-256 and Ed25519,
        256 bytes for RSA-2048, and so on — and is shown here base64-encoded.
      

      

        
      

      
      

    


    

      
7 Verify
        — ms
        not run
      

      

        Verifies the signature against the encoded message using the public key. In a
        real deployment the verifier would only ever have this key, never the private one.
      

      

        
      

    


    

      
8 Tamper test
        — ms
        not run
      

      

        Flips one bit of the signature and re-verifies. Verification should return false
        — this is the check that a signature actually protects the message.
